## Scope and method

What deck learns about the user, where it keeps it, for how long, who can read it, and what leaves the machine. Out of scope: what programs running inside deck do themselves, other machines, Windows.

Two read-only reviewers on 24 Nov 2026; a finding's letter is its reviewer. P: what deck keeps, where, how long, who can read it. Q: what leaves deck and what deck reads about the user.

They read every non-test file writer and all 73 non-test `tracing` calls of the four crates, the features of every runtime dependency (`cargo tree --locked -p deck -e normal` for the four release targets), the symbols and libraries of the built binaries, the committed recordings and fixtures, and ran a daemon with random secrets in its environment through a session, a successful upgrade, a failed one and `kill-server`, reading every file afterwards. Q-4 was checked by reading OpenCode's source at tag `v2.4.1` (commit `6f0514052a3c859894ad01bb14cc14dda1e44b96`).

Severity is `critical`, `high`, `medium`, `low` or `info`.

## What leaves the machine

Nothing, at runtime.

- deck's code has no TCP, UDP or DNS call; its only sockets are Unix sockets.
- The runtime dependency graph is 140 crates on macOS (plus `linux-raw-sys` on Linux), with no HTTP, TLS or DNS crate. `tokio`'s `net` is used for Unix sockets only, `time`'s `local-offset` reads the time zone, `clap` has no `env` feature, and `ghostty-vt` has `kitty-graphics` and `png` only: its `resources` module, which would write under the user's cache directory, is reachable only through two functions deck never calls, and its logger is not set.
- The binaries link `libSystem` and `libiconv` only, import no `getaddrinfo`, TLS or CFNetwork symbol, and hold one URL, clap's bug-report text.
- There is no telemetry, crash reporting, update check or self-update.
- At build time one build script uses the network: `ghostty-vt-sys` fetches `libghostty-vt` 1.0.1 from `release.files.ghostty.org`. The HTTP and TLS crates are on build edges only.
- Indirect paths, none of them a connection of deck's: programs deck starts by itself (shells, agents resumed after a restart, `opencode session list`), the outer terminal acting on OSC 52 and OSC 9, agents reading terminals through the control API (Q-3), and the installers.

### What deck reads about the user

- **Agent session listings** (`crates/deck-daemon/src/server/listing.rs`, parsers in `crates/deck-core/src/agent_sessions.rs`): only when an attached client sends `ListAgentSessions` (the restore dialog, three requests on opening, limit 50). Claude: `$CLAUDE_CONFIG_DIR/projects/*/<uuid>.jsonl` or `~/.claude/projects`, the newest 100 files, 256 KiB of each head. Codex: `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-*.jsonl`, up to 100 files, to the first `user_message`, 4 MiB each. OpenCode: a child `opencode session list`, since Q-4 in `~` only. Kept per session: id, title (80 cells), directory, time; memory only; sessions of every project are shown.
- **Hook payloads** (`crates/deck/src/agent_event.rs`): stdin read to its end, 1 MiB kept; never in argv; nothing printed. Claude and Codex: only `hook_event_name`, `notification_type`, `session_id` and `prompt` are read, and since Q-5 only the first line of the prompt (200 characters) is sent; `transcript_path`, `cwd`, `tool_input` and `tool_response` are dropped in the client. OpenCode: the plugin forwards six event types whole and the daemon parses them. The daemon keeps the status, a valid session id and the first prompt line; no payload is logged.
- **`config.toml`**: the daemon only; it holds no secret by design.
- **Client environment**: every client sends its whole environment (Q-10): each agent event ships the agent's environment and each completion `TAB` the shell's; held for the connection; only the three `DECK_*_ID` values are read.
- **Not in the spec's lists**: each terminal's foreground-process argv every second (the name is kept), its directory every 5 s, the host name (the OSC 7 host check), the outer terminal's name, version, colours, graphics and keyboard support, and the macOS font check (Q-9).

### What deck sends out of the process

- **Clipboard**: a program's OSC 52, OSC 1337 `Copy=` or OSC 5522 write goes to the session's most recently active client as OSC 52 (4 MiB, 16 MiB pending per client; dropped with no client). The client's mouse selection copies on release, and copy mode's `y` copies. Reads are denied. Nothing is logged or kept.
- **Outer terminal**: no window title; the OSC 9 body `<kind> needs you|finished · <space> › <panel>` (P-1); kitty images; queries.
- **To programs in deck**: `DECK*`, `TERM_PROGRAM=deck`, `TERM_PROGRAM_VERSION`; the outer terminal's name and version as the XTVERSION answer (also to a remote host over ssh, as the outer terminal would); colours (OSC 4, 10, 11).
- **`deck ls`, `--json`, `capture`, `stats`, completion**: names, titles, programs, directories, roots, pids, agent kind, status, source and session id for every session; up to 10,000 lines or 8 MiB of any terminal; to any process of the same user (Q-3).
- **Agent configs**: the hooks and the plugin hold only the fixed command with deck's absolute path. `deck hooks install --print` prints the whole would-be settings file, secrets included, on request; `docs/features/agents.md` now says so.

## The questions of requirement 2

- **Does anything leave the machine?** No (above).
- **Do logs contain user data?** No terminal contents, typed input, environment values, clipboard, titles, prompts or agent session ids. Lines that do hold user data: `deck daemon listening socket=<path>` (the user name in the path); `terminal exited at once ... program=<path>` and `restored terminal <program> exited at once` (no arguments); `shutting down: last session "<name>" killed from pid ...` (the session name; the spec said ids only); the duplicate session and space name lines; `upgrading: <binary>` and the first stderr line of the preflight; config notices that quote the user's own `config.toml`. Counts only: the 10-minute `stats:` line and `listed agent sessions kind= count= failed= ms=`. Two lines were fixed here: the failed restore named its panel, which can be a prompt's first words (P-2), and a parse error quoted the file (P-3), the one path found by which an environment value reached the log.
- **Does `state.json` hold anything beyond the layout and DECK-04's fields?** No session environment and no screen contents. Beyond DECK-04: `keep`, `exited`, `agent {kind, session_id}`, `name_source`, auto panel names (P-1), `--env` values and arguments (P-4).
- **Are secrets of the environment ever written to disk?** In normal operation, no. A random token in the creating client's environment was absent from every file after a session, a successful upgrade, an upgrade failed with `DECK_TEST_EXEC_FAIL=1` and `kill-server`; `crates/deck/tests/privacy.rs` now checks that on every run, with a restart too. The handoff file is unlinked before its first byte and closed on every failure path: none was left behind. Exceptions: `--env` values (P-4), agent settings in `backups/` (P-5), a core after an abort (P-6). On macOS the handoff's blocks are on the data volume for a moment (no fsync): accepted.
- **What reaches the repository?** `.gitignore` had `/target`, `/.worktrees`, `.DS_Store` and `.opencode/model-profiles.jsonc` (Q-6 adds four entries). E2E captures always go to `target/e2e-captures/` (also `compat/<case>/`), stress output to `target/stress/` (numbers and a failure string; uploaded by `stress.yml`). Fixtures are synthetic (`/home/u`, hand-made plists). The seven committed recordings are clean (only `deck@example.invalid` and a lazygit version). The e2e harness gives test daemons the developer's environment minus `ENV` and `DECK*`, so a capture can show one of its values, under `target/` only; CI sets no token there. The check on recordings had gaps (Q-2).
- **Retention: is anything kept forever?** Before this sub-spec: `state.json.bad-*`, `backups/*`, `daemon.log.1`, the lock files and the last `deck.upgrade.result`, and no command erased everything. Now `kill-server --forget` also deletes the `.bad-*` files and only the newest 3 backups of each file are kept (P-5). The log (10 MiB plus one rotated file), the locks and the last upgrade result stay; `docs/features/privacy.md` says how to erase everything.

## Fixes of sub-spec 03

- **Q-4**: `opencode()` in `crates/deck-daemon/src/server/listing.rs` starts one child with the session's `HOME` as its working directory, and nothing when the session has no `HOME` or a relative one (it would name a directory under the daemon's own; test `opencode_does_not_run_without_an_absolute_home`). The listing no longer reads the session's space roots. The child's `PWD` is set to that directory and its `OLDPWD` removed (test `the_opencode_child_gets_its_directory_as_pwd_and_no_oldpwd`): the session's own name the directory it was created in, usually a space root, and the review of this sub-spec found that OpenCode 2.4.1's `run` and `mini` commands take `PWD` for their working directory, so `session list` could come to do the same. A session whose space root is the home directory itself still lists there: that is the user's own configuration. The limit of two children at a time and the 8 s timeout stay.
- **P-2**: `Shared::notify` is split: `Shared::show` delivers a notice without logging it. A failed restore logs `could not restore terminal <id> (session <id>, space <id>, panel <id>): <reason>` and shows the user the notice with the names, as before. The reason still names the program's path.
- **P-3**: `persist::json_error` describes a JSON error by its kind and position (`unexpected value at line 12, column 40`), and both `persist::load` and `handoff::file::read` use it. An error of an already parsed value has no position, so `load` reads the text once more to find it.
- **P-5 (a)**: `forget_state` in `crates/deck/src/control.rs` also deletes every `state.json.bad-*`.
- **P-5 (b)**: `write_backup` in `crates/deck/src/hooks.rs` deletes all but the newest 3 backups of the same `<agent>-<file>` after writing one. The backup just written is never the one deleted, also when the clock went back. The copy of the file as it was before deck first touched it is therefore gone after the fourth change. The existing test `backups_never_overwrite_each_other` counted four backups after four changes; it now checks three distinct ones after three, and that a fourth gets a name of its own while the oldest goes.
- **Q-2**: `privacy_violations` looks for the home, the host name and the home prefixes in the text as it is and with its CSI sequences taken out, and for stray paths in the text with a word boundary where each CSI sequence was; a path also counts after `;` (an OSC parameter) and after `file://` and a host. `write_recording` checks the user and host names whatever their length (under 4 characters as whole words). The recorder sets `TZ=UTC`.
- **Q-3, P-4**: two rules in `skills/deck/SKILL.md` (so also in `deck guide`). Installed copies of the skill read `stale` in `deck skills status` until `deck skills install` runs again.
- **Q-5**: `request()` in `crates/deck/src/agent_event.rs` sends `clip_prompt` of the prompt. OpenCode's raw events are unchanged.
- **Q-6**: four lines in `.gitignore`.
- **The end-to-end test**, `crates/deck/tests/privacy.rs`: a daemon whose creating client has `DECK_PRIVACY_SECRET` and `PRIVACY_TOKEN`, a typed word, the token echoed on the screen, an OSC 52 copy, an OSC 2 title and a `UserPromptSubmit` prompt (both longer than 32 cells), all random. Every regular file under the home is read while it runs, after `deck upgrade`, after `kill-server`, after a restart and after a second `kill-server` (`nothing_private_is_on_disk_after_an_upgrade_a_stop_and_a_restart`), and after an upgrade that fails with `DECK_TEST_EXEC_FAIL=1` (`nothing_private_is_on_disk_after_a_failed_upgrade`): no value appears, as it is or in base64 at any alignment, and no `deck.handoff.*.tmp` is left. The one exception is the first 32 cells of the title or the prompt as `panels[].name` in `state.json`; `the_check_finds_what_it_looks_for` shows the check finds the same words in any other field or file.

## Differences from the audit's proposals

- **Q-2**: the audit asked for every check on the text with CSI removed. The stray-path check is not run on that text: `less` prints its search prompt as `/`, `CSI K`, then the pattern, which reads as the path `/line` once the CSI is gone, and the committed `less` recording would fail. A path whose first name an escape sequence parts from its `/` is therefore not seen; the names (home, host, `/Users/`, `/home/`) are. An escape sequence as a word boundary also refuses a relative path whose parts are coloured apart (`src`, a colour, `/main.rs`): a false alarm on the safe side, documented.
- **Q-2**: a name of 4 or more characters is still looked for anywhere in the text, as before, not only as a whole word.
- **P-1**: the e2e test also asserts the saved panel name is exactly 32 cells and starts with the title's, then the prompt's, first word, so a change of that decision shows in the test.

## What could not be checked

- **Q-4 by a run.** The reviewer's sandbox refused the local port OpenCode's service binds, so the finding rests on reading OpenCode 2.4.1. OpenCode 1.x was not read.
- **P-6 on Linux.** Whether a core is written depends on the system's settings; nothing was run on Linux.
- **Linux in general.** The tests of this sub-spec ran on macOS; CI runs them on Linux.
- **The handoff file's blocks on disk.** The file has no name, but its blocks are on the data volume until the descriptor closes; whether they can be recovered afterwards was not examined.
