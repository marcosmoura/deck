This report is written from an audit by read-only reviewers, whose notes held the evidence for every finding (measurements, attack strings, upstream line numbers) and are not kept in the repository; the analysis was not repeated.

## Scope and method

How deck could be abused by another local user, by a program running inside it, by a file or terminal output it reads, or through its dependencies and its release pipeline. Out of scope: other machines, network exposure (deck listens on no network port), Windows.

Four read-only reviewers on 24 Nov 2026, split by area; a finding's letter is its reviewer. A: the socket, directories, live upgrade, control API, hooks, skills and environment. B: terminal output, the emulator, images, the client and `unsafe`. C: dependencies, the build, CI, releases and the tap. D: the changes up to `d002f75`.

They read the code of the four crates and of the dependencies a finding touches (`ghostty-vt` 0.9.0, `clap_complete` 4.6.12), ran probes against a built daemon and emulator (memory and time for hostile sequences, replies to queries, completion in bash 5.3.20 and 3.2.57), checked both lock files against OSV and RustSec (`cargo-audit`, database of 22 Nov 2026), and compared the pinned action versions and the release checksums with their sources. Nothing was run against other machines.

Severity is `critical`, `high`, `medium`, `low` or `info`.

## Threat model

**Assets**

- The user's shells and programs: keystrokes and pastes (passwords included), screen and scrollback (daemon memory and the handoff snapshot), and the ability to run commands as the user.
- Each session's environment: the whole environment of the client that created it (tokens, API keys). It lives in daemon memory, is passed to terminals and is written to the handoff file. Every control client also sends its whole environment in `Hello`.
- The clipboard (OSC 52 forwarded to the outer terminal).
- Files the daemon reads as the user: kitty file mediums, agent transcripts, `config.toml`, `state.json`.
- Agent configuration deck edits: Claude `settings.json`, Codex `hooks.json`, the OpenCode plugin, the three skills directories.
- `state.json` (programs, arguments, `--env` additions, directories, agent session ids), `daemon.log`, backups of agent configs.
- The daemon process itself (every session dies with it) and the `deck` binary path used by hooks and upgrades.
- Release tokens and the tap.

**Actors**

- Another local user: can squat or race `/tmp` and read world-readable files; cannot signal the daemon or reach the socket.
- A program inside a deck terminal, same uid, unsandboxed: full control by design (the control API); not a boundary.
- A restricted program inside deck: an agent under a sandbox or a command allowlist, or a prompt-injected agent. The socket is a confused-deputy path for it: `new-terminal -- <cmd>` runs outside the agent's sandbox, and `send` types into other terminals, other agents' permission prompts included.
- Untrusted output (`ssh`, `cat` of a hostile file): escape sequences only (titles, OSC 7, OSC 52, kitty graphics, query replies).
- A hostile repository: file and directory names, project-level agent settings, binaries found through a relative `PATH` entry.
- A malicious dependency; a compromised GitHub token.
- Root and the same user outside deck are trusted.

**Trust boundaries**

1. The socket: a `0700` runtime directory plus the peer uid, checked by the daemon and, since this review, by every client (A-1).
2. The permissions of the runtime and state directories (A-1, A-2).
3. Signals (`SIGUSR2`, `SIGTERM`, `SIGINT`, `SIGHUP`): same uid or root only.
4. `deck.upgrade`, the preflight and `execve`; `Bye(Upgrading { exe })` and the client's `exec`.
5. PTY output into the OSC 7 scanner, the kitty file scanner and the emulator, then frames, the client and the outer terminal.
6. Control CLI output (`ls`, `capture`, `wait`, shell completion) into the invoking terminal, a shell or an agent's context.
7. Hooks, plugin and skill installed into agents' user-level configs.
8. Environment: client to daemon to terminals; `DECK_*` is reserved; the `DECK_TEST_*` seams.
9. `state.json` and the handoff file: restore and adoption start programs from them.
10. CI and release.

## Fixes of sub-spec 01

- **B-1.** `PngDecoder::decode_png` reads the size from the PNG's `IHDR` and refuses the image before decoding when `width × height × 4` is over the 64 MiB storage limit (the emulator answers `EINVAL`). After a PNG that declares over 1 MiB the inner decoder is replaced, which frees its buffer. The test also bounds the resident memory a refused image may cost. An image under the limit still costs its allocation (the note in B-8). Not covered by a test: that the buffer is freed (resident memory does not fall promptly on macOS).
- **A-1 (a).** The daemon checks the runtime directory again right after creating it: owner, mode `0700`, a real directory. One planted in between, or a link, is `UnsafeRuntimeDir`.
- **A-1 (b).** The control client reads the peer's uid (`getpeereid` on macOS, `SO_PEERCRED` on Linux) before it sends `Hello`; another user's socket gets nothing and the command fails. This covers `DECK_SOCKET` too.
- **A-1 (c).** The attach client makes the same check (`peer_cred()`), and executes the path of `Bye(Upgrading)` only when it is absolute, a regular file and owned by the user or root.
- **B-2.** The client builds at most 64 MiB of scaled canvases per draw (the rest on the next draws) and keeps at most 128 MiB of them alive in the outer terminal; a placement over that is not drawn until others leave. Virtual placements (one per image, bounded by the daemon's 64 MiB of storage per screen) are outside the budget.
- **D-1.** bash gets a deck-local completer: clap's script, and only the candidates that need no quoting (ASCII letters and digits, `_ - . / : = + @ , % ~`, and non-ASCII characters that are neither control nor whitespace). Other names are not offered in bash ([completion](../features/completion.md)).
- **C-1.** Every action is pinned by a commit SHA with its version in a comment, and mise-action has `version: 2026.11.13`. `.github/check-pins.sh` fails on anything else; it failed on the workflows as they were (13 unpinned actions, 4 mise-action steps without a version). The tap's `publish@main` is exempt until 02 pins it.
- **C-2, the job split.** The fix-up of release-please's branch is two jobs: `prepare` runs the checkout and the tools with no secret and uploads what changed; `commit` holds the token and runs only the artifact download and `gh`. What `prepare` uploads is still what gets committed to the release branch (DECK-32).
- **C-8, the procedure.** [architecture.md](../architecture.md#dependencies), "Updating `ghostty-vt`".

Left for sub-spec 02, found while fixing A-1 (the "A-1 residual" row): the peer check covers the socket, not the files beside it. When the socket does not answer or is refused, `deck kill-server` falls back to `SIGTERM` on the pid it reads from `deck.lock` (`crates/deck/src/control.rs:609-621`). The explicit `deck upgrade` reads the same pid and the marker and sends `SIGUSR2` (`perform`, `crates/deck/src/upgrade_cmd.rs:97-131`); its only connection (`daemon_version`) reports a version and gates nothing. Only the automatic upgrade on a protocol mismatch (`upgrade_older_daemon`, `crates/deck/src/control.rs:76-86`) is behind a checked connection. Both commands read those files after the client's one `lstat` of the runtime directory, so a directory planted in the same narrow window could name another process of the user.

## Fixes of sub-spec 02

Made on `2d3ac66`, each finding confirmed there first: all still held. One moved to the performance sub-specs (A-8, at the end).

- **A-1 residual.** `deck kill-server`'s fallback and `deck upgrade` read the pid through one function that inspects the runtime directory again, without following a link, and refuses it unless it is a directory of mode `0700` owned by the user. Nothing in it is read and no signal is sent before that.
- **A-2.** The daemon creates the state directory `0700` and its log `0600`, and sets both modes at every start, so a directory or a log made looser earlier is tightened. `deck hooks install` creates the state directory and `backups/` `0700`. The daemon's two lock files (`deck.lock`, `state.lock`) are created `0600`, and one that was `0644` is tightened when the daemon opens it. A daemon that takes over in a live upgrade opens nothing: it sets the modes of the state directory, the log and the two inherited locks itself.
- **A-3, B-3, D-2.** An OSC 7 path with a control character (C0, DEL or C1) is dropped by the scanner. `deck ls --tree` and the completion descriptions print `?` for each control character in a name, a root, a program or a directory. Every `--json` document writes DEL and the C1 controls as `\u00XX` escapes (JSON's own escaping stops below U+0020), so a program name or a real directory read from the operating system prints none raw either, and the document decodes to the same values.
- **A-4.** The skill and [the control API page](../features/control-api.md) say that allowing the socket lets an agent run programs outside its sandbox and type into every terminal, and that the names, titles and directories of `deck ls` are data from other programs, like captured text.
- **A-7.** The hook command is always an absolute path: the `PATH` entry of `deck` as written when it is absolute and is the running binary, otherwise the binary's own path. Hooks installed earlier with the bare name keep working, `deck hooks status` reports them as `stale`, and the next `deck hooks install` replaces them. A `PATH` entry inside a version-specific directory does not survive an upgrade ([agents](../features/agents.md)).
- **A-9.** `deck daemon --adopt` takes a descriptor of 3 or more, and `own_fd` refuses the standard ones whoever asks.
- **A-10.** An agent's session id is stored only when it is one deck could resume (the check the resume command already made); any other is dropped. The OpenCode tracker, in `deck-core`, ignores ids over 128 bytes.
- **B-4.** The daemon removes every control character from a title; a title left empty is no title.
- **B-5, the caps.** A clipboard write is forwarded only as plain text of at most 4 MiB: the emulator refuses a larger one, and deck drops one with no `text/plain` part. A client's queue holds at most 16 MiB of copies that wait; one more is dropped and the client stays connected. Only a copy is dropped for that budget, never another message behind one.
- **B-9, the lookup and the throttle.** The operating system is asked for every terminal's directory, also one that reports with OSC 7. A report holds until the process changes directory with no new report, so one that some output carried is dropped at the shell's next `cd`. Directory changes reach the clients through the throttle titles use (one view per 100 ms and a last one).
- **B-10.** The client leaves every ESC byte out of a bracketed paste, as the daemon does for `deck send --paste`.
- **B-11.** `own_fd` returns an error for a standard descriptor and for a number that is not open, and `prepare_adoption` refuses a handoff file that names a descriptor twice; the callers cannot be `unsafe`, since they are outside the platform modules. On macOS the listening check asks with `connect`, which a listening socket refuses with `EOPNOTSUPP` and which changes nothing, instead of `listen`. `signal` and the two `waitpid` wrappers refuse pid 0 and pids that do not fit a positive `pid_t`. [architecture.md](../architecture.md) lists the three `libc` uses.
- **C-3, the script.** `install.sh` runs from a `main` called on its last line, downloads from GitHub with `--proto '=https' --tlsv1.2`, and stages the binary under a fresh `mktemp` name. `packaging/install-check.sh` installs a fake release from a `file://` directory and checks all of it, a wrong checksum included; it fails on the script as it was (it wrote through a planted link).
- **C-4, the pin.** The tap's action is pinned at `a2ff0e50a6e36c2511dba1cfd0dd57ccafb27813`, the tap's `main` on 24 Nov 2026 (verified with `git ls-remote`), and the pin check has no exemption left. A fix in the tap now reaches deck only when the pin is moved.
- **C-5.** `mise.lock` records the download URL and the SHA-256 of every tool of `.mise.toml` for `macos-arm64`, `macos-x64`, `linux-x64` and `linux-arm64` (written by mise 2026.11.13; `just lock-tools` rewrites it for the same platforms), and the four workflows set `MISE_LOCKED=1`, so mise installs a tool only as the lock records it; the pin check fails on a workflow that uses mise-action without it. Checked on macOS arm64 with a fresh mise directory: in locked mode `just` installs with the lock as it is, fails with a changed checksum in the lock, and a version with no entry fails. The two gaps are at the end.
- **C-6.** The tarball carries `LICENSE`. The workspace crates are `publish = false`, and `deny.toml` has `wildcards = "deny"` with `allow-wildcard-paths = true`.
- **C-7.** [workflow.md](../workflow.md#commits-the-flow-may-make) says when `Cargo.lock` may change, and the reviewer's role checks it.
- **C-9.** `SECURITY.md` asks for reports through GitHub's private vulnerability reporting, which the owner has to switch on in the repository's settings. `.github/dependabot.yml` covers `github-actions` and `cargo`, weekly, with `chore(deps)` commits.
- **C-10.** Every checkout has `persist-credentials: false`; the release build's mise-action has `cache: false`; a pull request that touches the release workflow or a manifest also packs the tarball, and uploads nothing.
- **D-4.** A completion request is answered only after the `agent-event` guard, so a `COMPLETE` in an agent's environment cannot make a hook print or fail.
- **The bash line.** `eval "$(COMPLETE=bash deck)"`, which also works in bash 3.2.

**Moved to the performance sub-specs (measured in 05, fixed in 06): A-8.** Since A-1 the environment reaches only a daemon whose peer was checked to be the same user, which closes the security concern. What is left is the cost of sending it with every hook call, and a timing. Sending only the `DECK_*` variables on a connection that creates no session was written and taken out again: with it the end-to-end test `kill_server_during_the_handoff_is_answered_by_the_new_daemon_which_then_stops` fails. `deck kill-server` waits 1 s for its answer and then falls back to `SIGTERM`; in that test the handoff is held for 1.5 s, and the daemon stops for `SIGTERM` instead of for the request. With the whole environment in `Hello` the test passes. Sub-spec 04 measures both before anything changes.

**Two gaps in C-5.** Rust has its version in `mise.lock` and no checksum: mise installs it with rustup and does not lock it. cargo-deny has no macOS x64 entry (mise recorded none); no workflow installs it on that platform.

## `cargo-deny`

`just audit` runs `cargo deny --locked check` (cargo-deny 0.22.1, pinned in `.mise.toml`) with the root `deny.toml`, and CI runs it on the Linux runner. It covers the four release targets, build dependencies included:

- **Advisories**: RustSec; yanked and unmaintained crates are errors. No entry is ignored.
- **Licences**: MIT, Apache-2.0, ISC, BSD-3-Clause, Zlib, Unicode-3.0; exceptions for `option-ext` (MPL-2.0, linked through `ghostty-vt` and `dirs`) and for `webpki-roots` and `webpki-root-certs` (CDLA-Permissive-2.0, build time only).
- **Bans**: one version per crate. Seven older versions that only an upstream release removes are skipped, each with its reason: `nix` 0.28 and `cfg_aliases` 0.1 (`portable-pty`), `thiserror` 1 and `thiserror-impl` 1 (`filedescriptor`), `miniz_oxide` 0.8 (`png`), `syn` 2, `getrandom` 0.2 (`ring`, Linux build only). `wildcards` was `allow` in sub-spec 01; since sub-spec 02 the workspace crates are `publish = false` and it is `deny` with `allow-wildcard-paths = true`, which allows only their path dependencies on each other.
- **Sources**: crates.io only.

`Cargo.lock` lists four versions of `nix`, but only two are in deck's dependency graph (0.28 through `portable-pty`, 0.32 as a build dependency of `zip`); 0.29 and 0.31 belong to optional dependencies that no feature turns on, so they are neither built nor counted.

Run on 24 Nov 2026 on macOS:

- The pinned cargo-deny 0.22.1, run directly: `advisories ok, bans ok, licenses ok, sources ok`.
- `just audit` passes. On the machine it ran on, `cargo deny` resolves to an older cargo-deny 0.22.0 in `~/.cargo/bin` rather than the pinned one, so that run was 0.22.0's; it passes all four checks too. CI installs the pinned version with mise.
- The checks can fail (0.22.0): without the skip list `bans` fails on exactly those seven crates, and without `Zlib` `licenses` fails.
- After sub-spec 02's change of `wildcards`: `just audit` passes (0.22.0 again): `advisories ok, bans ok, licenses ok, sources ok`.
